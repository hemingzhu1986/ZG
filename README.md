# 织光内容雷达 v2

每天自动把「欧美＋中国」的热点、文娱与文化观察素材整理成 Telegram 日报，并从中挑出几个适合 **AI 短剧** 的选题。
**不依赖任何人的电脑**：跑在 GitHub Actions 或任意 Linux 服务器上；**纯 Python 标准库，零依赖**；默认**不使用任何付费 API**。

---

## 1. 和旧版的区别

| | 旧版 | v2 |
|---|---|---|
| 运行位置 | Mac 开机 + Codex 定时任务 | 云端（GitHub Actions 或任意服务器） |
| 采集 | 代码只自动采 5 个源，其余靠 Codex 浏览网页 | 全部由代码自动采集，每个来源独立隔离、失败可见 |
| 每条内容 | 标题＋简介（人工/Codex 写） | 标题＋简介（大模型或规则降级，见 §5） |
| 缺稿/漏发 | 无告警 | 多次补跑 + watchdog + 管理员私信告警 |
| 重复发送 | 账本防重 | 账本防重 + **冻结当日文本**（补发时内容与第一次一致）|
| 短剧选题 | 不做（规范里禁止） | 单独发送到独立群，不混入每日精选 |
| 已移除 | Variety、旧版自动拆条、讨论群文案、`assert` 校验 | —— |

## 2. 每天发什么

| 消息 | 时间（北京） | 内容 | 发到 |
|---|---|---|---|
| 每日精选·国际 | 10:00 起 | 目标共 25 条（不凑数，不足就少发并报告缺口）。每条：中文标题（可点击）＋简介＋来源/热度/标签 | `TELEGRAM_CHAT_ID` |
| 每日精选·国内 | 同上 | 保底 6 条、上限 10 条 | 同上 |
| 影视日榜 | 同上 | 电影/剧集各 Top 5（TMDB 站内趋势，**不是票房/收视**）。无 `TMDB_API_KEY` 则不发 | 同上 |
| 成人平台行业观察 | 同上 | 主流媒体的**非露骨**行业/监管/研究报道，无内容不发（边界见 §8） | 同上 |
| AI 短剧选题 | 同上 | 3 则选题卡：数据依据、冲突、前三集、反转、钩子、AI 可行性、风险 | `DRAMA_CHAT_ID`（默认不发到主频道）|
| 周回顾 | 周五 17:30 起 | 本周已发条目去重后的精选 25 条＋本周短剧选题回顾 | 主频道 |
| 运行报告 | 每次 | 入选条数、缺口、各来源状态、发送结果 | `ADMIN_CHAT_ID` |

单条消息最长 3800 字（Telegram 上限 4096）；**按整条内容打包，绝不在一条中间截断**。示例见 `examples/sample_output_2026-11-04.md`。

## 3. 数据源（`config/sources.json`）

**我在开发环境里没有外网，无法联网验证任何一个接口。** 单元测试只验证解析逻辑。所以首次部署后请先运行一次 `doctor`（见 §6），以它的输出为准。

| 来源 | 地区 | 状态 | 说明 |
|---|---|---|---|
| 谷歌趋势 RSS（美国） | 国际 | 稳定 | 沿用旧版已在用的接口 |
| 维基百科浏览榜（en） | 国际 | 稳定 | 官方公开 API；与前一天对比，剔除常年高居的“常青词条” |
| THR、NPR | 国际 | 稳定 | 沿用旧版 RSS |
| Deadline、滚石、梗百科 KYM、Dexerto | 国际 | **实验** | RSS 地址未经验证 |
| Mastodon 热门链接 | 国际 | **实验** | 公开接口，内容偏新闻/科技 |
| B站全站榜 | 国内 | 稳定（有风险） | 旧版已用；海外 IP 可能被拦，失败时自动切到 RSSHub 备用源 |
| 微博热搜、知乎热榜 | 国内 | **实验** | 官方无开放接口，依赖公开页面/RSSHub，随时可能失效 |
| 短剧榜单聚合（第三方转载 DataEye） | 国内 | **实验** | 页面超过 3 天未更新会被判定为“已过期”并剔除，不会把旧榜当今天的 |
| TMDB 电影/剧集日趋势 | 国际 | 需免费密钥 | 需遵守 TMDB 条款（见 §8） |
| 成人平台行业观察 | 国际 | 稳定 | Google News RSS＋主流媒体域名白名单 |
| **Reddit** | 国际 | **默认关闭** | 见下 |
| **人工投稿 `/add`** | 任意 | 稳定 | 见 §7，用来补足抓不到的来源 |

**关于 Reddit（重要）**：旧版 Reddit 占比最高，是因为 Codex 用的是真实浏览器和 Mac 的家庭 IP。2026 年 5 月起 Reddit 封锁了未登录的 `.json` 访问，云服务器 IP（包括 GitHub Actions）被重点拦截，官方 API 的新申请据报道也已关闭。因此 v2 在服务器上**拿不到 Reddit**，已默认关闭，并用维基、谷歌趋势、KYM、媒体和人工投稿补位。**日报的内容构成会和旧版明显不同。** 如果你有可用的出口 IP，把 `reddit_*` 源的 `enabled` 改成 `true` 即可。

## 4. 筛选逻辑

1. **采集**：所有来源并发抓取；任何一个失败只影响它自己；主源失败时备用源（`role: fallback`）自动接手。
2. **清洗**：剔除商业推广词、露骨内容；体育赛事打标记（每日最多 1 条）。
3. **去重**：URL 规范化 + 标题相似度（中英文分词）；同一事件只留热度最高的一条，其他来源记为“另见”。
4. **跨天去重**：近 3 天发过的事件不重复，除非热度上升 ≥40%（标记“📈昨日追踪”）。
5. **打分**：`(0.6×热度 + 0.15×时效 + 0.25×跨源印证) × 来源权重`
   热度 = 名次 `1/(1+0.12×(名次−1))` 与搜索量/播放量对数中的较大者；时效按 36 小时半衰；每多一个独立来源印证 +0.5（封顶 1）；人工投稿 +0.2；体育 ×0.6。
6. **配额选取**：单源上限（`config/settings.json` 的 `caps`）、媒体类新闻合计 ≤6、体育 ≤1、国内 6–10。不够 25 条就少发。
7. **编辑加工**：见 §5。

## 5. 标题简介与短剧选题：三档降级

没有任何一档会中断发布。

| 档位 | 条件 | 标题/简介 | 短剧选题 |
|---|---|---|---|
| ① 大模型 | 配置 `LLM_*`（免费档即可） | 中文标题＋≤80 字简介，只依据输入内容，传闻标“未证实” | 3 张完整选题卡 |
| ② 免费翻译 | 无 LLM | 免费翻译接口（非官方，无保障）＋原文摘要 | 仅“素材候选卡”：主题、情绪、冲突类型、可参考类型 |
| ③ 原文 | 翻译也失败 | 英文原文，标“（未译）” | 同② |

短剧选题的机制：先按“情绪冲突主题”（关系背叛、怀旧重来、身份反转、职场阶层、家庭代际、悬疑怪谈、AI科技……）给当天入选条目打分，并要求 3 张卡主题互不相同；再交给大模型写成卡片。程序会校验：必填字段齐全、`basis_ids` 必须是当天真实存在的条目（防止编造数据依据）。提示词在 `config/prompts/drama_zh.txt`，规则：只借情绪与结构，不借具体事件/真人/现有作品，人物一律虚构。
**无 LLM 时不会冒充完整选题。**

## 6. 部署

### 需要你准备的东西
1. 一个**公司名下**的 GitHub 账号或组织（不要用个人号，否则又依赖了个人资源）。
2. 在 Telegram 的 @BotFather 创建机器人，得到 `TELEGRAM_BOT_TOKEN`；把机器人加为主频道**管理员**（需发消息权限）。
3. 各聊天 ID：把机器人拉进对应频道/群后，在频道发一条消息，浏览器打开 `https://api.telegram.org/bot<TOKEN>/getUpdates`，找 `chat.id`（频道形如 `-100…`）。你自己和机器人私聊发一句话，同样能查到自己的 ID，填到 `ADMIN_CHAT_ID` 与 `ADMIN_USER_IDS`。
4. （可选）免费的大模型密钥、TMDB 免费密钥。
5. **所有密钥只放进 GitHub Secrets（或服务器的 `.env`），不要写进代码、不要发到聊天里。**

### 方案 A：GitHub Actions（零服务器，免费）
1. 新建**私有**仓库，上传本目录全部内容（含 `.github/`）。
2. Settings → Secrets and variables → Actions，按 `.env.example` 添加 Secrets（空的也要建，值留空）。
3. **先用测试频道**：把 `TELEGRAM_CHAT_ID` 指向一个测试频道。
4. Actions → radar → Run workflow：先选 `doctor` 看各来源真实状态；再选 `daily` 强制发一次。
5. 看管理员收到的运行报告，把失败的来源在 `config/sources.json` 里 `"enabled": false` 或换 URL，提交。
6. 稳定后把 `TELEGRAM_CHAT_ID` 改成正式频道。
7. **强烈建议加一个外部定时器**，因为 GitHub 的定时任务是尽力而为：官方明确说高负载时会延迟，近期还有私有仓库完全不触发的反馈。用 cron-job.org 之类的免费服务，每天北京 10:05 向 `POST https://api.github.com/repos/<组织>/<仓库>/actions/workflows/radar.yml/dispatches` 发送 `{"ref":"main"}`，请求头带一个只授权该仓库 Actions 读写的细粒度令牌。令牌请用公司/机器人账号生成。
8. 每次运行约 1–2 分钟、每天至多 5 次，通常远低于免费额度，但以你的 GitHub 套餐为准。

### 方案 B：任意 Linux 服务器（最稳）
```bash
git clone <你的仓库> /opt/radar && cd /opt/radar
cp .env.example .env && nano .env        # 填入密钥
mkdir -p logs
set -a && . ./.env && set +a && python3 -m radar doctor
crontab deploy/crontab.example           # 每 10 分钟触发；程序自己判断是否到点、是否已发
```
建议选亚洲机房（B站海外访问更稳）。云厂商的免费/低价小机型即可。也可用 `deploy/Dockerfile`。

## 7. 日常运维

| 场景 | 做法 |
|---|---|
| 想知道今天各来源是否正常 | 看管理员私信里的运行报告；或手动运行 `doctor` |
| 日报没发 | 14:05 会收到 watchdog 告警；看 Actions 日志；`state/ledger.json` 里每条消息有 `sent/failed/pending` |
| 状态 `pending` | 说明上次发到一半崩溃、不确定是否送达，**程序不会自动重发**。去频道确认后运行 `python -m radar resolve --date 2026-11-05 --key daily_intl#1 --status sent`（或 `failed`）|
| 临时少发/多发 | 用环境变量 `RADAR_SETTINGS_JSON='{"targets":{"daily_total":20}}'` 覆盖 |
| 补充抓不到的来源 | 管理员在和机器人的私聊里发 `/add 链接 一句话备注`，进入下一期候选（保留 3 天）。只有 `ADMIN_USER_IDS` 里的人有效 |
| 新增/删除数据源 | 编辑 `config/sources.json`（类型：`rss`、`google_trends`、`wikipedia_top`、`bilibili_ranking`、`weibo_hot`、`mastodon_trends`、`tmdb_chart`、`html_links`）|
| 只预览不发送 | `python -m radar build --out out` |

## 8. 已知限制与风险（请读）

1. **所有数据源接口都没有经过联网验证**，实验性来源失败属正常，以 `doctor` 为准。
2. **Reddit、TikTok、Instagram、X、小红书、抖音的原生榜单没有免费且稳定的服务器端方案。** 现在通过 KYM、媒体报道、第三方转载和人工投稿间接覆盖。
3. **国内来源偏薄**：目前只有B站、微博、知乎、短剧榜单聚合；后三者都是实验性。国内条数保底 6 条在来源失败时可能达不到，报告会如实标出。
4. **B站榜的播放量是累计值，不是当日增量。**
5. **没有大模型时，英文条目的简介质量明显下降**，短剧选题只有素材候选。免费档额度和可用模型会变，所以代码里不写死模型名；免费档条款通常允许服务商使用提交内容，因此程序只发送公开的标题与摘要。
6. **程序不核验事实**，只做格式、来源、重复和商业词检查。大模型被要求只依据输入，但仍可能出错，建议抽检。
7. **TMDB**：免费密钥通常限非商业使用，且需在展示处标注归属（已自动附上）。你们团队是否算商业使用请自行核对其条款。
8. **成人平台行业观察的边界**：只收主流媒体域名白名单内的非露骨报道（行业、监管、年龄验证、研究）；过滤露骨关键词；不链接任何成人站点，不提供内容榜单、演员信息或观看入口。如需调整，改 `config/sources.json` 里 `adult_news` 的域名白名单。
9. **GitHub 定时任务不保证准时**，公开仓库 60 天无提交会被自动停用（私有仓库不受此规则影响，但仍有延迟/漏触发报告）。已用补跑、watchdog 和外部触发降低风险。
10. 免费翻译接口是 Google 的非官方端点，随时可能失效，仅作兜底。
11. 账本在 Actions 里靠“运行结束时提交 `state/`”持久化；极端情况下（运行被强杀）可能出现一次重复发送。方案 B 无此问题。

## 9. 目录

```
config/settings.json    时间窗、配额、条数目标、去重参数
config/sources.json     数据源清单（启停、权重、备用源）
config/lexicon.json     商业/露骨/体育词表、标签与短剧主题词表
config/prompts/         大模型提示词（标题简介、今日概述、短剧选题）
radar/                  代码（sources/ 里是各数据源适配器）
tests/                  41 个离线测试：python3 -m unittest discover -s tests
examples/               示例输入与示例输出
.github/workflows/      GitHub Actions 工作流
deploy/                 crontab 与 Dockerfile（方案 B）
state/ archive/         运行时写入：账本、历史、冻结文本、每日归档
```
