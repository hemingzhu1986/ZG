# 织光内容雷达 v2

每天北京时间 **11:00** 自动把「欧美＋中国」的热点、文娱与文化观察素材整理成 Telegram 日报，并从中挑出几个适合 **AI 短剧** 的选题。
**不依赖任何人的电脑**：跑在 GitHub Actions 或任意 Linux 服务器上；**纯 Python 标准库，零依赖**；默认**不使用任何付费 API**。

---

## 1. 每天发什么：一个渠道一条消息

**每个渠道单独发一条消息，不同渠道不混在一起。** 消息标题固定为「渠道名＋资讯」，例如：

> 🔍 **谷歌趋势资讯** ｜ 📚 **维基百科资讯** ｜ 😂 **梗百科资讯** ｜ 🔥 **微博热搜资讯** ｜ 🎶 **抖音热榜资讯** ｜ 📺 **B站全站榜资讯** ｜ 📊 **JustWatch 美国影视榜资讯** ｜ 🎬 **豆瓣榜单资讯** ……

| 项目 | 说明 |
|---|---|
| 渠道范围 | 谷歌趋势、维基百科、梗百科、TikTok、Reddit（4 个板块各一条）、12 家行业媒体（各一条）、微博、抖音、知乎、小红书、B站、JustWatch 影视榜、豆瓣榜单、抖音短剧日榜、团队投稿 |
| 每条消息 | 该渠道当天最多 N 条（`config/sources.json` 里每个渠道的 `show`，默认 4–10 条），每条＝**中文标题（可点击）＋120–220 字简介＋热度/标签**；一个渠道**恒为一条消息**，放不下的低排名条目整条舍弃，绝不拆成两条、也不在条目中间截断 |
| 没有内容的渠道 | 当天不发，并在运行报告里列出（“今日无内容的渠道”） |
| 跨渠道的同一事件 | 各渠道消息各自完整保留，只标注“另见：某某渠道”，不互相删除 |
| 榜单渠道 | JustWatch（电影＋剧集）、豆瓣（热门电影＋热门剧集）、抖音短剧日榜，各一条，内部按榜单分组 |
| 成人平台行业观察 | 独立一条，只含主流媒体的非露骨行业/监管/研究报道 |
| AI 短剧选题 | 3 则选题卡，发到 `DRAMA_CHAT_ID`（默认不发到主频道） |
| 周回顾 | 周五 17:30 起，仍是一条跨渠道的本周精选（需要的话可以改成按渠道拆分） |
| 运行报告 | 发给管理员：各渠道条数、无内容渠道、剔除统计、翻译统计、发送结果、异常来源 |

每天大约 **20–30 条消息**（取决于有多少渠道有内容）。为避开 Telegram 每分钟约 20 条的限制，消息之间间隔 3.5 秒，全部发完约 2 分钟。
想把 12 家行业媒体合并成一条「行业媒体资讯」：把它们在 `sources.json` 里的 `channel` 改成同一个名字即可（同名渠道自动合并）。

条目格式（示例见 `examples/sample_output_2026-11-04.md`）：

```
🔍 谷歌趋势资讯
2026-11-04 周三
按谷歌美国 24 小时搜索量排序

1. 标题（可点击链接）
简介：3–5 句，交代谁、做了什么、背景、各方反应
热度 · 另见：其他渠道 #标签
```

## 2. 内容规则

- **政治类、AI/科技类资讯：全部过滤**（日报与榜单；大模型会再做一次主题判定，并从备选里补位）。
  规则在 `config/lexicon.json` 的 `politics_re / ai_re / ai_cs_re`，开关在 `config/settings.json` 的 `filters`。
  过滤是关键词＋大模型判定，**会有少量误伤**（例如标题里带“总统”二字的娱乐新闻）；剔除数量和类别会写进运行报告，便于你调整词表。
  榜单例外：抖音短剧榜里的“AI短剧/漫剧”是**形态标签**，属于 AI 短剧组需要的信息，不按“AI 资讯”过滤；榜单只按标题过滤政治类。
- **日报不做“露骨内容”筛选。** 唯一保留的底线是：针对真人的**未经同意传播的私密影像**（“泄露的裸照/私密视频/sex tape”类）。
- **成人平台行业观察**保持“非露骨”边界：只收主流媒体域名白名单内的行业、监管、年龄验证、研究报道；不链接任何成人站点，不做内容榜单。
- 商业推广词（赞助、优惠码、带货……）仍会剔除。

## 4. 筛选逻辑

1. **采集**：并发抓取；任一来源失败只影响它自己；主源失败时备用源自动接手。
2. **清洗**：剔除商业推广与私密影像泄露；屏蔽政治、AI/科技；体育打标记（每日最多 1 条）。
3. **去重**：**渠道内**按 URL＋标题相似度去重；跨渠道的同一事件各留一条，互相标“另见”。近 3 天发过的不重复，除非热度上升 ≥40%（标记“📈昨日追踪”）。
4. **打分**：`(0.6×热度 + 0.15×时效 + 0.25×跨源印证) × 来源权重`。
5. **渠道内选取**：每个渠道按平台名次（或综合分数）取前 N 条（N 为该渠道的 `show`），体育每渠道 ≤1；有大模型时每渠道多选 2 条备选。
6. **写简介**：抓取文章正文片段作为输入（不转载、不存档）→ 大模型用自己的话写 120–220 字简介，并再判定一次是否政治/AI 类，命中的剔除并由备选补位。
7. **榜单**：JustWatch／豆瓣／短剧日榜分组展示。

## 5. 全部翻译成中文

**所有外文（英文、日文、韩文）的标题和简介都会翻成中文**，人名、作品名写中文译名并括注原名，例如“卡迪·B（Cardi B）”。四级保障，逐级降级，永不中断发布：

| 级别 | 做法 | 质量 |
|---|---|---|
| ① 免费大模型（推荐） | 配置 Gemini 等免费档后，用自己的话写 120–220 字中文简介，并括注译名 | 最好 |
| ② 大模型补译 | 大模型输出里仍夹带外文、或漏掉的条目，自动再试一次 | 好 |
| ③ 免费机器翻译 | Google 非官方接口 → MyMemory（填邮箱后每天 5 万字，无需注册）；长文按句子分块；带缓存 | 一般，只能直译来源摘要 |
| ④ 标注“未译” | 以上都失败时保留原文并明确标“（未译）”，运行报告里会统计 | —— |

**强烈建议配置免费大模型**，没有它简介只能是来源摘要的机翻。步骤（只需一个 Google 账号，不用信用卡）：
1. 打开 aistudio.google.com/apikey，登录 Google 账号，点 **Create API key**，复制密钥。
2. GitHub 仓库 → Settings → Secrets and variables → Actions：
   - 在 **Secrets** 里添加 `LLM_API_KEY` = 刚复制的密钥。
   - `LLM_PROVIDER` = `gemini`、`LLM_MODEL` = `gemini-flash-lite-latest` 建议放在 **Variables** 标签页（不是 Secrets）：Secrets 里的值会在日志中被自动打码成 `***`，不方便排查；放 Variables 则日志里看得见。放 Secrets 也能用。
   - 模型名建议用带 `-latest` 的别名（如 `gemini-flash-lite-latest`、`gemini-flash-latest`），Google 会让它始终指向当前可用的版本，不容易因旧模型下线而失效。**不要选** pro / gemma / image / tts 类模型（免费档通常没有额度或不支持）。
3. Actions → radar → Run workflow → 选 **llmtest**：先检查密钥是否有效、列出推荐模型，再用两条样例试译。**失败时会打印 Google 返回的具体原因**（429=额度用完或该模型无免费额度；404=模型名不存在；400=模型不支持；403=密钥无权限）。你填的模型不可用时，程序运行时会**自动改用一个可用的 Flash 模型**，并在运行报告里告诉你改用了哪个。
4. （可选）添加 Secret `MYMEMORY_EMAIL`，填任意有效邮箱，机器翻译兜底的每日额度从 5000 字提到 5 万字。

免费档有每分钟和每天的次数限制、模型名也会变：程序在调用之间留了 7 秒间隔，遇到限流会自动等待重试；大模型整天都调不通时，运行报告会写明原因，日报自动降级为机器翻译，不会中断。免费档条款通常允许服务商使用提交的内容，所以只发送公开的标题与摘要。

## 6. 部署与运维

### 首次部署（GitHub Actions）
1. 公司名下的私有仓库，上传全部内容（含 `.github/`）。
2. Settings → Secrets and variables → Actions，添加 Secrets：
   `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`、`ADMIN_CHAT_ID`、`ADMIN_USER_IDS`（必填）；`LLM_PROVIDER`、`LLM_API_KEY`、`LLM_MODEL`（强烈建议，见 §5）；`DRAMA_CHAT_ID`、`MYMEMORY_EMAIL`、`TMDB_API_KEY`、`CRAWLORA_API_KEY`（可选，没填的不用建）。
3. Settings → Actions → General → Workflow permissions 选 **Read and write permissions**。
4. Actions → radar → Run workflow：先 **test**（逐个测试频道并报告原因），再 **llmtest**（检查翻译），再 **doctor**（检查所有来源），最后 **daily**（强制发一次）。

### 定时：不依赖 GitHub 的定时任务

**GitHub 的 `schedule` 定时触发是共享调度器，不保证准时，甚至会长期不触发，换套餐也没用。** 手动触发（`workflow_dispatch`）是可靠的，所以：

**方案 A（推荐先做，免费，约 15 分钟）：外部定时器 → 触发 GitHub 工作流**
用 cron-job.org（免费）按时向 GitHub 发一个触发请求。工作流本身已支持，不用改代码。
- 请求：`POST https://api.github.com/repos/<账号>/<仓库>/actions/workflows/radar.yml/dispatches`
- 请求头：`Authorization: Bearer <令牌>`、`Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28`、`Content-Type: application/json`
- 请求体：`{"ref":"main"}`，成功返回 **204**
- 令牌：GitHub → Settings → Developer settings → Fine-grained tokens；只授权这一个仓库，权限 **Actions: Read and write**；**到期后会静默失效，请设日历提醒**。
- 时区选 Asia/Shanghai，建 6 个任务（全部幂等，多触发无害）：每天 11:05、11:35、12:15、13:45，以及 15:05（监控），周五另加 17:35、18:15（周回顾）。

**方案 B（最稳，完全不依赖 GitHub）：自己的服务器常驻运行**
程序自带常驻调度（`python -m radar serve`）：每 5 分钟检查一次，到点就发，失败 15 分钟后重试，窗口过后没发完会私信管理员。不需要 cron。
```bash
git clone <仓库地址> /opt/radar && cd /opt/radar
cp .env.example .env && nano .env        # 填密钥
docker compose up -d --build             # 或：用 deploy/radar.service 做 systemd 服务
docker compose logs -f                   # 看日志
```
所有“免费服务器”（Oracle、Google Cloud 等）注册都要信用卡验证，且免费额度和可用性会变；也可以直接用约 4 美元/月的小型 VPS。内存 512MB 以上即可。

**建议两者并用**：A 先上线，B 作为备份。两边同时触发是安全的：账本保证同一天同一条消息只发一次。

### 日常运维
| 场景 | 做法 |
|---|---|
| 今天各来源是否正常 | 看管理员私信的运行报告；或 Actions 选 `doctor` |
| 日报没发 | 15:05 会收到告警，私信里有具体错误；`state/ledger.json` 记录每条消息状态 |
| 状态 `pending` | 上次发到一半崩溃、不确定是否送达，**不会自动重发**。去频道确认后 `python -m radar resolve --date 2026-11-05 --key daily_intl#1 --status sent`（或 `failed`） |
| 补充抓不到的来源 | 管理员私聊机器人：`/add 链接 一句话备注`，进入下一期候选（保留 3 天） |
| 调整过滤 | 改 `config/lexicon.json` 词表，或 `config/settings.json` 的 `filters` 开关 |
| 临时改条数 | 环境变量 `RADAR_SETTINGS_JSON='{"targets":{"daily_total":20}}'` |

## 7. 已知限制（请读）

1. **所有新增来源都未经联网验证**，实验性来源失败属正常。抖音、知乎、TikTok、豆瓣、JustWatch 都是非官方/公开接口，随时可能改版或拦截云服务器 IP。
2. **小红书没有公开接口；Reddit、TikTok 原生榜在云服务器上没有免费稳定方案。**
3. **过滤会误伤**，也可能漏掉：关键词覆盖不了所有政治/科技表述。
4. 简介的事实依据只有来源提供的摘要和正文片段；**程序不核验事实**，大模型也可能出错，建议抽检。
5. 榜单口径各异（JustWatch 是用户关注度，抖音短剧榜是热度），名次不可跨榜比较；B站播放量是累计值。
6. TMDB（备用）免费密钥通常限非商业使用，且需标注归属（已自动附上）。
7. GitHub 定时任务可能延迟/漏触发；公开仓库 60 天无提交会被停用。
8. 免费翻译接口是非官方端点，随时可能失效，仅作兜底（连续失败 3 次自动停用）。

## 8. 目录

```
config/settings.json    时间窗（11:00）、配额、条数、过滤开关
config/sources.json     数据源清单（启停、权重、备用源）
config/lexicon.json     政治/AI/商业/体育词表、标签与短剧主题词表
config/prompts/         大模型提示词（简介、概述、短剧选题）
radar/                  代码（sources/ 是各数据源适配器）
tests/                  107 个离线测试：python3 -m unittest discover -s tests
examples/               示例输入与输出
.github/workflows/      GitHub Actions 工作流
deploy/ + docker-compose.yml   服务器常驻部署（serve）：Dockerfile、systemd、crontab 备选
state/ archive/         运行时写入：账本、历史、冻结文本、每日归档
```
